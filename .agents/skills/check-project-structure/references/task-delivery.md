# 任务交付 SOP

适用于从需求开始执行并交付结果的项目任务。根据任务大小调整记录粒度。

1. **确定交付目标。** 从请求和现有材料提取范围、交付形式和可观察的验收条件。能合理推断时，采用可逆的假设继续执行，并记录影响交付的假设。
2. **执行任务。** 查看已有项目约定和可复用的技能或工具。把正式修改写到对应项目目录。
3. **验收结果。** 按任务的实际使用方式检查交付物。例如，脚本要运行命令并检查退出状态，文档要检查链接和打开效果。记录验证结果与仍待核实的事项。
4. **交付成果。** 按任务约定的形式交付文件或结果。交付说明包括成果、验证结果，以及用户需要知道的假设或限制。

## 任务归档

任务产物需要在项目内留档时，按需建立 `tasks/<任务名>/`。

- `scratch/` 存放有复查价值的草稿、试验结果和中间数据。一次性文件可以放系统临时目录。
- `result/` 存放最终交付物。
- `record.md` 记录关键决定、验证结果和交付物的相对路径。

小任务可以把结果文件和 `record.md` 直接放在任务目录下。
